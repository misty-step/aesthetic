# CATALOG.md — the report component catalog, in words

The design language every generative-report consumer inherits
(aesthetic-926): one component catalog, one aesthetic, every fleet report
surface — Glass's live agent-status feed, fleet-retro's daily/weekly digest,
glance's generated documentation, and the deck — reads as the same system,
not three independently reinvented ones.

**Code lives in `glance-catalog` (misty-step/glance,
`crates/glance-catalog`), not here.** This repo owns the prose identity and
the published gallery; that repo owns the Rust types, validation, and
renderer. Read this file for _why the catalog is shaped the way it is_; read
that crate's source for the exact schema.

**Rendered exemplar of every primitive:**
<https://bastion.tail5f5eb4.ts.net/artifacts/a/catalog/> — generated by
`glance-catalog/examples/exemplar.rs`, not hand-mocked.

## Why one catalog, not three

Before aesthetic-926, three fleet surfaces had independently built the same
idea: glance-next's `PageSpec`/`Component` (a synthesized documentation
page), weave/fleet-retro's `RetroSpec` (a synthesized activity digest), and
Glass's `SurfaceKind` (a ported copy of the open-source Sideshow project's
9-kind live-stream vocabulary). An oracle research pass found glance-next's
and fleet-retro's `Hero`/`Narrative` components had converged on the same
shape independently — strong evidence these are the right primitives, not a
coincidence to arbitrate by picking a winner. The fix: name the convergence
and merge it into one shared crate every consumer rides, instead of a fourth
report kind reinventing the same wheel a fourth time.

## The two tiers

**Tier 1 — leaf surfaces** (content containers, Sideshow-proven): markdown,
code, diff, terminal, image, mermaid, metric, callout. These carry raw
content and need no mandated order — a live stream (Glass) posts them
chronologically, one small surface at a time, exactly the job Sideshow
already proved out.

**Tier 2 — structural components** (report grammar,
glance-next/fleet-retro-proven): hero, narrative, table, timeline,
disclosure. These compose the leaf tier into an editorial document with a
mandated shape — hero first, disclosure last, progressive order in between
— the job a single synthesized report (fleet-retro's daily, glance's
generated doc page) needs and a live stream does not.

A live stream and a synthesized report are different consumption modes over
the _same_ content primitives, not two catalogs. `glance-catalog`'s
`LayoutProfile` (`STREAM` / `REPORT`) is the one seam that varies: same
`Component` enum, same validator, a profile parameter instead of a
hardcoded ordering rule.

## What "the aesthetic every consumer inherits" means concretely

- **One design law, not per-surface CSS.** Every structural component's
  renderer emits this kit's `.ae-*` classes — `.ae-hero`, `.ae-section`,
  `.ae-table`/`.ae-plate`, `.ae-trail`, `.ae-stat-badges`,`.ae-cite` — never
  a bespoke per-consumer class. A consumer's own page-shell CSS (max-width,
  spacing, heading resets) is the only local override budget; component
  chrome is not a place for consumer-specific reinvention. fleet-retro's own
  aesthetic-926 migration is the proof: its pre-existing `.retro-hero`/
  `.retro-section`/`.retro-table` classes are gone, replaced by this kit's
  classes, with a rendered-output parity check (before/after visible-text
  line count and tag-count histogram both identical) proving the
  consolidation lost no content.
- **Citations are structured, not string-formatted.** Every citation —
  glance's source-code line range, fleet-retro's evidence-pack item — is an
  `InlineNode::Cite { text, ref_id }` node; `ref_id` is opaque, and each
  consumer supplies its own `ref_id -> href` resolver at render time. The
  model or collector that builds a spec never hand-writes an `<a href>` or
  formats a citation string itself — that stays deterministic, per-consumer
  code, decoupled from the shared type.
- **Empty and demoted states are structural, not an afterthought.** A
  `Table`/`Timeline` with zero rows must carry an explicit `empty_note` — a
  malformed spec that silently omits the note fails `validate()`, it does
  not render a blank section. A `Table` may also carry a `demoted_note` for
  rows that exist but carry no signal (fleet-retro's "N repo(s) swept with
  no activity") — folded into one muted line instead of a table padded with
  dead rows.
- **No universal caps that don't belong to every consumer.** `Hero.stats`
  has no upper bound in the shared crate, even though glance's own
  single-page-doc design keeps its own visual band tight (2-4 chips) — that
  cap is glance's business rule, layered on top locally, not a catalog
  invariant. A consumer with more summary numbers than fits one visual band
  is not forced to silently drop the excess to satisfy someone else's
  design choice.

## Consumers (adoption order)

1. **fleet-retro** (`weave/apps/fleet-retro`) — first real proof consumer
   beyond glance-next itself. `RetroSpec` composes the shared `Hero`/
   `Narrative`/`Table`/`Timeline`; `Footer`/`Receipts`/`Provenance` stay
   local report-specific extensions (no second consumer independently built
   an equivalent, so folding them into the shared catalog would arbitrate a
   winner where there is nothing to merge with).
2. **glance-next** (`crates/glance-gen`) — the crate generalizes this
   repo's own `PageSpec`/`Component`/`validate_for_kind` pattern; retargeting
   glance-gen's own renderer onto it is a separate, later ticket
   (glance-922) so this migration does not collide with glance's own
   in-flight work.
3. **Glass** — its `SurfaceKind` already carries Sideshow's tier-1 leaf
   vocabulary; adopting the shared crate and gaining tier-2 structural
   components is a later, separate ticket (glass-912), scoped narrower than
   the full catalog (text/narrative, image, code, metric — a strict subset).
4. **The deck / Bridge** — not yet started.

## What this doc is not

Not a prompt kit. Teaching a model to emit catalog-conformant JSON from raw
context is a separate, later child of the same epic — this doc and the
published gallery are the _reference_, not the _generator instructions_.
